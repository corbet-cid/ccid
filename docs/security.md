# Security and dependency visibility (R47)

What we do about dependencies and vulnerabilities is stated in every repository, generated by `ccid render`
and never hand-written. The text is fixed (no data files, no network), contains no contact address and names no
forge, so it is the same on every forge.

| Where | What ccid owns |
|---|---|
| `README.md` | one status line between the markers, after the first title (at the top of the body when there is none). A repository without a README gets none. |
| the policy file | a block at the end of the file GitHub reads: `.github/SECURITY.md`, else `SECURITY.md`, else `docs/SECURITY.md`; a root `SECURITY.md` is created when there is none. Text a person wrote is never touched. |
| release notes | `ccid release` appends a "Security and dependencies" section to the notes. |

The policy block says what runs (Renovate with OSV vulnerability alerts, grouped updates merged when green,
the dependency dashboard issue), that copies run no CI and why, and how to report a problem: the forge's issue
tracker, or GitHub's private vulnerability report on a public GitHub copy where it is enabled.

Applies at `render_schema = 3` only, and not to a project that lists upstream CI files (a contributed project
gets nothing of ours, R10, R11). Between the markers `<!-- ccid:security:begin ... -->` and
`<!-- ccid:security:end -->` a hand edit is drift; a file without the block yet is a declared transition for
`render --check` (the next render adds it). A symbolic-link README or policy file is refused.
